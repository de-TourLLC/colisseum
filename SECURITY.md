## 2. Reporting a Vulnerability

If you discover a security vulnerability **within the obfuscator engine or codebase itself**:

### How to Submit (Repository-Only Flow)
* **Do NOT** open public Issues, Pull Requests, or Discussions for undisclosed security flaws.
* Use GitHub's **Private Vulnerability Reporting**:
  1. Go to the **Security** tab of this repository.
  2. Click on **Advisories** under *Reporting*.
  3. Click **Report a vulnerability** to open a private disclosure draft with the maintainers.

### What to Include in Your Report
1. A clear description of the vulnerability in the obfuscator.
2. Proof of Concept (PoC) code or steps to reproduce the issue locally.
3. The potential impact of the flaw.

## 3. Scope & Out of Scope

### In Scope
* Code execution vulnerabilities, memory safety flaws, or improper file handling within the obfuscator engine.

### Out of Scope (Will Be Closed Without Action)
* **Reverse engineering or deobfuscation:** Code obfuscation is a protection layer, not an absolute cryptographic guarantee. Deobfuscating or reversing an output is expected behavior over time and is not considered a software vulnerability.
* **Misuse of the tool:** Malicious scripts, exploits, or TOS-violating code obfuscated by third parties using this software.
